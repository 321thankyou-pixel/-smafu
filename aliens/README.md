# エイリアンズ コードフォーム選択 PoC（v12）

iPhone Safari 実機で「コードカードをタップ → フォーム候補から選択 → 表示が即時変更 →
再読み込みしても選択が残る」を成立させるための最小PoC。

- 本体: `index.html`（外部依存なし・1ファイル完結）
- 生成元: `../tools/`（後述）

## 受入条件（CODEX_START_HERE.md より）

1. コードカードをタップ
2. 複数のコードフォーム候補が表示
3. 1つ選択
4. ダイアグラム／フォーム表示が即時変更
5. ページを再読み込み
6. 選択したフォームが保持されている

ページ上部に「iPhone Safari 受入テスト」パネルを常設し、①〜⑤の判定を画面上に表示する。
⑤が緑（OK）になり、保存したフォーム名が表示されれば合格。

## 検証状況

| 環境 | 実施 | 結果 |
|---|---|---|
| WebKitGTK 2.52（Safari と同一の WebKit エンジン）+ WebDriver、実HTTPサーバ経由 | 済 | 45/45 PASS |
| Chromium（iPhone 13 エミュレーション・実タップ・実HTTPサーバ経由） | 済 | 66/66 PASS |
| 静的レンダラ(Python)と動的レンダラ(JS)の出力一致（全106フォーム） | 済 | 一致 |
| **iPhone Safari 実機** | **未** | **ユーザー確認待ち** |

WebKitGTK は Safari と同じ WebKit だが iOS Safari そのものではない。
**実機で①〜⑤を確認するまで「Safari対応済み」とは扱わない。**

## v9/v11 から直した実際の不具合

1. **ピンクの「次」コード `Baug7(b9)` にフォーム候補が無く、タップしても選べなかった**
   → 曲中で使う全38コード（`N.C.` を除く37コード）にフォームを登録。未登録はゼロ。
2. **ダイアグラムの押弦ドットが JS 再描画時に見えなかった**
   → `.dot` に width/height が無く 0×0 だった。CSS で実寸を指定。
3. **10フレット以上のフォームがダイアグラム化できなかった**（`x9A9A9` / `x8A898`）
   → ハイフン区切り表記（`x-9-11-9-10-9`）に対応するパーサへ変更。
4. **`F7 x8A898` は構成音が誤りだった**（2弦が G# になり、7th の A が出ない）
   → 全フォームを構成音で機械検証する仕組みに置き換え、誤ったフォームは採用しない。
5. **JSが落ちると画面が白いまま原因が分からなかった**
   → `window.onerror` を画面上のエラー枠に表示。譜面は静的HTMLとして事前描画。

## 初版レビューで見つけて直した欠陥

1. **セーハで鳴ってしまう弦を検証していなかった**（`gen_voicings.py`）
   押弦5本以上でセーハ判定に入るとき、セーハ下の開放弦しか弾いておらず、
   ミュート指定の弦を見逃していた。その結果 `F9 1x1213` は5弦が実際には B♭ で鳴り、
   F9 の構成音に無い音が混じっていた（`G9 3x3435` / `G9(13) 3x3455` /
   `F#7(b9) 2x2323` / `D9 10-x-10-11-10-12` も同じ理由で誤り）。
   セーハ範囲内の開放弦・ミュート弦を不可にして、いずれも正しいセーハ形に差し替えた。
2. **開放弦を含むローコードでナットが描かれず、窓が2Fから始まっていた**
   `CM7 x32000` が「2F〜」表示になり、ローコードが移動フォームに見えていた。
   開放弦があり押弦が5フレット以内なら必ずナットから描くようにした（106形中38形が該当）。
3. **5フレット窓に収まらないフォームでドットが図の外に描かれる経路があった**
   現データでは未発火だが、窓外になる場合は明示的に表記エラーにした。
4. **フォームを持たない `N.C.` をタップすると受入テスト③が赤い NG になった**
   候補が無いのは仕様なので、NG にせず理由を表示するようにした。
5. **第1候補（index 0）を選び直すと、保存されているのに⑤が「保存なし」と表示された**
   復元件数を「0 以外」でなく「復元できたもの全部」で数えるようにした。
   範囲外の壊れた保存値は読み捨てるだけでなく削除する。
6. **`env(safe-area-inset-bottom)` 非対応環境で padding 宣言ごと破棄される**
   素の `padding` を先に置くフォールバックを追加。
   ダイアグラムのフレット枠は CSS Grid から flexbox に変更。
7. **再生中に毎フレーム3枚のカードを `innerHTML` で作り直していた**
   コードが変わったときだけ再描画するようにした（実機での再生時のカクつき対策）。

なお `.nav` / `.vopt` などのレイアウトは CSS Grid と `env()` を使うため、
**動作の下限は iOS 11.2 相当**。それ以前の iOS は対象外（意図的な割り切り）。

## Safari 向けに入れた対策

- JS は ES5 相当で記述（アロー関数・テンプレートリテラル・オプショナルチェーン不使用）
- 背景タップで閉じる領域を `<div>` ではなく `<button>` に（iOS で div の click が拾われない件）
- `touch-action:manipulation` / `-webkit-tap-highlight-color`
- シート表示中の背景スクロール固定と復帰（`position:fixed` + スクロール位置復元）
- `-webkit-overflow-scrolling:touch`、`env(safe-area-inset-bottom)`
- localStorage はプライベートブラウズ等の例外を捕捉し、使えない場合はメモリへ退避したうえで
  「保存一時」と画面に明示する（黙って失敗しない）

## 演奏設定（チューニング・カポ・キー・テンポ）

この譜面のコード名は「**半音下げチューニングで押さえる形**（Play: G）」で書かれている。
実際に鳴る音はそれより半音低く、原曲キー F# と一致する。この前提が画面から読み取れないと、
U-FRET などの原曲キー表記と見比べたときに半音ずれて混乱するため、設定として明示している。

- **チューニング**: 半音下げ / レギュラー
- **カポ**: 0〜7フレット
- **コード表記**: 「押さえる形」（この譜面の基準）/「実音」（実際に鳴る音の名前）
- **テンポ**: 40〜200（初期値 85）

設定は `aliens.settings.v1` として端末内に保存され、
「押さえる形のキー → 実際に鳴るキー → 原曲キーと一致するか」を常時表示する。

`実音` 表記にすると、U-FRET の原曲キー表記と同じコード名になる。対応は次のとおり
（テストで固定している）。

| 押さえる形 | 実音 | 押さえる形 | 実音 |
|---|---|---|---|
| CM7 | BM7 | Am7 | Abm7 |
| D/C | Db/B | A7 | Ab7 |
| Bm7 | Bbm7 | Dm7 | Dbm7 |
| Em7 | Ebm7 | B7 | Bb7 |
| F#m7 | Fm7 | E7 | Eb7 |
| GM7 | GbM7 | F#7 | F7 |
| C#m7-5 | Cm7-5 | Baug7(b9) | Bbaug7(b9) |

フォーム辞書とダイアグラムは「押さえる形」で管理しており、表記を切り替えても
押さえ方は変わらない（保存済みのフォーム選択も影響を受けない）。
カポを付けた場合、ダイアグラムのフレット番号はカポからの数として読む。

## 歌詞の扱い（重要・設計上の制約）

**歌詞はこのリポジトリに一切置かない。** 生成物 `index.html` にも含めない。

理由: このリポジトリは public であり、GitHub Pages で公開する。歌詞は言語の著作物で、
Web への掲載は公衆送信にあたるため、管理団体（JASRAC / NexTone 等）の許諾が必要になる。
YouTube やブログサービスに歌詞を載せられるのは、そのプラットフォームが包括契約を
結んでいるからであって、GitHub Pages はその対象ではない。

**代わりに、利用者が自分の端末に入力し、localStorage にだけ保存する方式を採る。**

### 位置は拍単位で持つ

歌詞は小節単位ではなく**拍単位**で保持する。1小節に複数の断片を置けて、1拍ずつ動かせる。

- 保存キー: `aliens.lyrics.v1`（`{"<0始まりの小節index>.<0始まりの拍index>": "歌詞"}` の JSON）
  - 例: `{"8.0": "…", "8.2": "…"}` = 9小節目の1拍目と3拍目
  - 旧形式の `"8"`（小節のみ）は `"8.0"` として読み込む
- 曲全体は 126小節 / 502拍（125小節が4拍、2/4ブレイクの1小節が2拍）。
  拍の移動は「曲頭からの通し拍番号」に変換して行うので、小節をまたいでも
  2/4小節をまたいでも正しく動く

### 入力方法

- **小節番号つき**: `M9 歌詞` / `9: 歌詞` / `9<タブ>歌詞`
  - 拍まで指定するなら `M9.3 歌詞`（9小節目の**3拍目**。拍は1始まりで書く）。省略すると1拍目
- **番号なし**: 1行＝1小節。「開始小節」から順に各小節の1拍目へ割り当て（空行はその位置を空に）
- 非空行の6割以上が番号つきに見えるときだけ番号つきとして解釈する

### 位置の微調整

- **小節をタップ** → その小節の拍ごとに入力欄が並ぶ。各行の `←` `→` で**1拍ずつ移動**
  （小節をまたいでも動く。移動先が埋まっていれば動かさず、その旨を表示する）
  - 移動すると、シートは断片を追いかけて移動先の小節に切り替わる
- **全体をずらす**: `←1拍` `1拍→` `←1小節` `1小節→`。
  1つでも曲の範囲を外れる場合は何も動かさない（部分的にずれた状態を作らない）
- 譜面の各小節は**拍のマス目**で歌詞を表示するので、どの拍に乗っているかが目で見て分かる
- ナビの大きい歌詞表示は、その小節の断片を並べ、**いま鳴っている断片を濃く**表示する

### その他

- 「書き出す」で `M<n> 歌詞` / `M<n>.<拍> 歌詞` 形式のテキストに戻せる（バックアップ用・往復可能）
- 「歌詞を全部消す」は歌詞のみ削除。「保存を消す」（受入テスト用）はフォーム選択のみ削除

**このページはネットワークへ一切送信しない。** `fetch` / `XMLHttpRequest` / `sendBeacon` /
`WebSocket` を使っておらず、外部CDNも読み込んでいない。テストでこれを機械的に確認している。

**Safari の注意**: ITP により、長期間アクセスのないサイトのスクリプト書き込みストレージは
消えることがある。入力後は「書き出す」で控えを取るよう画面上でも案内している。
保存に失敗した場合は黙って成功したように見せず、画面に警告を出す。

**1小節＝1行に正規化する。** 改行・タブは空白1つにまとめる。
こうしないと「書き出す→取り込む」の往復で2行目以降が失われる。

**もし将来、公開ページに歌詞を載せたくなった場合**は、曲ごとの管理団体を
JASRAC 作品データベース（J-WID）や NexTone の作品検索で確認し、
インタラクティブ配信（歌詞）の許諾申請が必要になる。どこも管理していない曲は
権利者への個別交渉になる。

## 歌詞機能のレビューで見つけて直した欠陥

1. **空行で既存の歌詞を消せなかった。** 画面には「空行はその小節を空にします」と書いてあるのに、
   実装は非空行しか書き込まず、既存の歌詞が残っていた。
2. **改行入りの歌詞が「書き出す→取り込む」で失われた。** 2行目以降が小節番号の無い行になり、
   取り込み時に黙って捨てられていた。1小節＝1行に正規化して往復可能にした。
3. **「数字＋半角スペース」で始まる行を小節番号と誤認していた。** 行頭が数字の歌詞が
   並ぶと番号つきモードに誤判定し、指定した開始小節を無視していた。半角スペース書式を廃止した
   （タブ・全角スペースは残す）。
4. **保存に失敗しても成功したように見えていた。** `localStorage` の容量超過を握りつぶしており、
   画面には取り込み成功と出るのに再読み込みで全部消えた。失敗を検出して警告するようにした。
5. **壊れた保存値を受け入れていた。** 配列や範囲外の小節番号が復元され、件数表示と
   書き出し内容が食い違っていた。キーの形式と範囲を検証するようにした。

また、番号つきモードで小節番号の無い行を黙って捨てていた点も、
取り込み後に「N行は取り込めませんでした」と報告するようにした。

## フォーム辞書の作り方（`../tools/`）

```
python3 tools/gen2.py       # 定番形＋探索 → 構成音を検証 → tools/voicings.json
python3 tools/build_app.py  # measures.json + voicings.json → aliens/index.html
```

`tools/gen_voicings.py` に各コードの構成音定義と検証ロジックがある。判定は以下の全てを満たすもののみ採用:

- 鳴る弦の音がすべてそのコードの構成音であること
- 必須音（ルート・3rd/sus・7th・指定テンション）がすべて含まれること
- オンコードは最低音が指定ベース音であること
- 押弦4本以内（セーハ考慮）、4フレット幅以内
- 鳴る弦が連続（6弦が鳴っているときの5弦ミュートのみ許可）

`定番形` = 人が与えた定番シェイプのうち検証を通ったもの、`探索` = 探索で見つけたもの。
どちらも構成音は機械検証済み。

### 既知の割り切り（意図的にそうしている点）

- **セーハの判定を厳しめに倒している。** セーハは「最低フレットで1弦まで届く」ものだけを
  想定しているため、人差し指で低いフレットを押さえつつ薬指で上を部分セーハする
  9th系の定番グリップ（`F9 x87888` / `Bm7 x24242` / `F#m11 x-9-11-9-12-9` など）は
  「押弦5本」と見なされて落ちる。**弾けるのに落ちる方向の誤りだけで、
  弾けない・音が違う形が通ることはない。** 全37コードとも候補は2〜3件残っている。
- **`diagram_html()`（Python側）は `voicings.json` が6要素・0〜24の正しい形式である前提。**
  形式チェックは生成器（`gen2.parse`）側にある。`voicings.json` を手編集する場合は
  必ず `python3 tools/gen2.py` で作り直すこと。
- 開放弦と6F以上の押弦が混在する12フォーム（`E7 076700` など）は、窓が高い位置から
  始まりナットは出ない。○×は左の弦ラベル側に出るため表記としては正しい。

## 自動テストの流し方

```
python3 -m http.server 8765 --bind 127.0.0.1 &
node tools/test_chromium.js http://127.0.0.1:8765/aliens/index.html   # Chromium(iPhone13)
Xvfb :99 -screen 0 400x900x24 & 
DISPLAY=:99 python3 tools/test_webkit.py http://127.0.0.1:8765/aliens/index.html  # WebKit
```

レンダラ一致の確認:

```
python3 tools/check_renderers.py
```

WebKit 側は `apt-get install webkit2gtk-driver xvfb` と `pip install selenium` が必要。
Chromium 側は Playwright が必要（`test_chromium.js` 冒頭の require パスを環境に合わせる）。
`file://` ではなく必ず HTTP 経由で開くこと（`about:blank` / `set_content` では
localStorage が永続せず、再読み込み保持の検証にならない。これは v11 のテストの限界だった点）。
